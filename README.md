# Clip4Clicks

**Produce short-form video, gate it behind a human, post it from real phones.**

A small-team content + commerce engine: a VPS produces videos (creator clips, stock
reels, generative spec-ads, dropship product ads), every one waits for a human yes,
and approved videos are posted from real Android handsets driven by AI.

Runs on a €20 box. Deploys with **zero API keys** — every integration degrades to a
clear "skipped, here's the missing key" instead of failing.

---

## Architecture

```
┌─ VPS (no phones) ──────────────────────────────────────────────┐
│  API + Worker + Scheduler · Postgres · Redis                   │
│                                                                 │
│  PRODUCE ─────────────────────► GATE ─────────► post_queue      │
│   clip      (yt-dlp + ffmpeg)   status =                        │
│   reel      (Pexels/Pixabay)    pending_review                  │
│   spec-ad   (Higgsfield)        ↑ human approves                │
│   product-ad(Seedance/fal)        via MCP/Telegram              │
│                                                                 │
│  /api/bridge/*  ◄── claim · download · report ──┐  (Bearer auth)│
└─────────────────────────────────────────────────┼───────────────┘
                                                  │ Tailscale/HTTPS
┌─ Operator desktop (Tauri app) ───────────────────┴───────────────┐
│  Bridge poller → Mobile-Use (localhost:8000) → ADB → 📱 phones   │
└──────────────────────────────────────────────────────────────────┘
```

**Why split:** Mobile-Use drives phones over USB/ADB, so it runs where the phones
are — the operator's desktop, never the VPS. The VPS produces and gates; the desktop
executes and reports back.

## Production paths

| Path | Input | Engine | Endpoint |
|---|---|---|---|
| **Clip** | creator VOD / stream URL | yt-dlp + ffmpeg (+ DeepSeek scoring, fal captions) | `POST /api/clips/generate` |
| **Stock reel** | a brief | DeepSeek script + Pexels/Pixabay | `POST /api/reels/generate` |
| **Spec-ad** | brief or product URL | Higgsfield (Kling cheap / Sora premium) | `POST /api/specads/generate` |
| **Product ad** | product photo | Seedance 2.0 reference-to-video via fal | `POST /api/productads/generate` |

All four land in the same review gate. Approved product ads post with the store link
and a per-platform UTM appended to the caption.

## The two human gates

Nothing reaches a real account without approval:

1. **Clips** — `GET /api/clips/review-queue` → `POST /api/clips/:id/approve` | `/reject`
2. **Outreach & engagement** — DMs and comment replies are *staged*, never auto-sent:
   `GET /api/outreach/review-queue`, `GET /api/engagement/queue` → approve/reject

## Quick start (VPS)

```bash
git clone https://github.com/MouhamedN96/Clip4Clips.git /opt/clipforge && cd /opt/clipforge
./scripts/bootstrap.sh            # generates secrets + brand
nano config/.env                  # paste API keys (see below)
node scripts/preflight.mjs        # readiness matrix: LIVE / FALLBACK / OFF
```

**Dedicated box:** `./scripts/deploy.sh` (builds, starts, self-verifies).

**Shared box** (already running Coolify/Traefik/other services) — use the prod compose,
which drops the bundled nginx and binds the API privately:

```bash
docker network create traefik-proxy    # once, if a proxy network isn't already there
docker compose --env-file config/.env -f docker-compose.prod.yml up -d --build
```

> `docker restart` does **not** reload `config/.env`. After changing env vars you must
> recreate containers (`docker compose ... up -d`).

See `docs/DEPLOY-SHARED-HOST.md` and `QUICKSTART.md`.

## Keys

Everything is optional; features light up as keys land. Re-run `preflight.mjs` after edits.

| Key | Unlocks | Without it |
|---|---|---|
| `DEEPSEEK_API_KEY` | highlight scoring, scripts, localized hooks | naive fixed windows |
| `FAL_KEY` | Whisper captions **and** Seedance video generation | no captions; product-ad path off |
| `PEXELS_API_KEY` / `PIXABAY_API_KEY` | stock-reel path | that path off |
| `HIGGSFIELD_API_KEY` | generative spec-ads | that path off |
| `WHOP_API_KEY` | billing / subscription webhooks | billing off |
| `BRIDGE_TOKEN` | desktop bridge auth (falls back to `API_SECRET`) | bridge disabled (503) |

`API_SECRET`, `POSTGRES_PASSWORD`, `REDIS_PASSWORD` are generated by `bootstrap.sh` —
don't hand-edit. **Never commit `config/.env`** (it is gitignored).

## Posting: Mobile-Use + the desktop bridge

Set `POST_EXECUTOR=desktop` on the VPS so the worker **skips** the post / outreach /
engagement queues and the desktop owns them.

The desktop app (`src-tauri/`, branch `yaatal/windows-desktop-alpha`) polls:

| Endpoint | Purpose |
|---|---|
| `GET /api/bridge/posts/claim` | atomically claim one approved post job |
| `GET /api/bridge/clips/:id/file` | download the produced mp4 |
| `POST /api/bridge/posts/:id/result` | report posted / failed |

All `/api/bridge/*` require `Authorization: Bearer <BRIDGE_TOKEN>` (constant-time
compare, **fails closed** if unset). Setup: `src-tauri/MOBILE-USE-SETUP.md`.

Rate limits protect account durability: ≥15 min between posts per device, ≤5 DMs per
device per day (`POSTING_MIN_INTERVAL_MS`, `ENGAGEMENT_MAX_DMS_PER_DAY`).

## Operating it (MCP)

The control surface is MCP, so any agent (Claude Code / Codex) can run the loop and
report over its own channel:

```bash
claude mcp add clipforge -s user -e CLIPFORGE_API_URL=http://127.0.0.1:3000 \
  -- node /opt/clipforge/src/mcp/server.mjs
cp -r skills/clipforge-operator ~/.claude/skills/
```

23 tools:

- **Produce** — `queue_clip` · `queue_reel` · `queue_specad` · `queue_product_ad`
- **Clip gate** — `review_queue` · `approve_clip` · `reject_clip` · `clip_status`
- **Outreach gate** — `outreach_review_queue` · `stage_outreach` · `approve_outreach` · `reject_outreach`
- **Devices** — `list_devices` · `device_status` · `post_clip`
- **Engagement** — `scan_comments` · `reply_comment` · `dm_commenter` · `engagement_queue` · `approve_engagement` · `reject_engagement`
- **Overview** — `list_clients` · `brand`
